# Web 管理端与刷新优化

管理端直接运行在 Q8B，调用本项目 GPIO 驱动。默认模拟模式，可在 macOS/Linux 上完成上传和预览，不操作 GPIO。此服务不部署到云端，浏览器连接设备本机服务。

## 安装

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-web.txt
```

Q8B 硬件模式还需安装 GPIO 依赖：

```sh
.venv/bin/python -m pip install -r requirements.txt
```

建议 Python 3.10+。现有命令行驱动仍可单独使用，无需安装 Web 依赖。

## 启动

直接启动服务，打开页面后自动连接，无需管理口令。

```sh
.venv/bin/python -m e6.web
```

默认只监听 `http://127.0.0.1:8080`，并明确显示“模拟模式”。上传 PNG/JPEG/WebP，选择抖动和画面适配方式，生成预览后点击刷新。全白、色条也先预览再提交。模拟模式使用独立状态文件，不影响硬件状态。

Q8B 核对 [接线表](q8b-wiring.md) 后，启用硬件并允许局域网访问：

```sh
sudo .venv/bin/python -m e6.web --hardware --host 0.0.0.0
```

浏览器打开 `http://Q8B的IP:8080`。DESPI 接口默认映射为 gpiochip4 上 SDI=88、SCLK=89、CS=90、DC=92、RES=110、BUSY=68；3V3 接 Q8B 物理针脚 17（或 1），GND 接 20。程序参数 mosi/clk/rst 分别对应 SDI/SCLK/RES。可使用 `--chip`、`--mosi`、`--clk`、`--cs`、`--dc`、`--rst`、`--busy` 覆盖；BUSY 极性可用 `--busy-level` 设置。

本服务使用 Waitress 单进程多线程提供 HTTP，不启用 Flask debug。页面与 API 无需口令，不开放跨域访问。HTTP 适用于受信任局域网；跨不可信网络时使用 SSH 隧道或 HTTPS 反向代理，勿直接向公网暴露。网页中的状态表示软件任务阶段，不是独立读取的电源/面板健康遥测。

## 新增图像处理

- EXIF 方向校正、透明区域合成白底。
- 默认横屏 720×480，可选竖屏 480×720；等比完整保留（白边）或居中裁剪填满。横屏直接编码为原始 720×480 扫描帧，每行 360 字节；竖屏顺时针旋转到原始帧，预览执行逆变换。
- 六色最近色量化，支持无抖动、Floyd–Steinberg、Atkinson 蛇形误差扩散和 Bayer 4×4 有序抖动。Atkinson 仅扩散 6/8 误差，可能牺牲部分色调层次；Bayer 呈现规则纹理，不保证优于误差扩散。
- 默认照片增强：保持色调的自动色阶、轻微增饱和与反锐化；可改为中值降噪/柔化，或关闭预处理。
- 可调整亮度（0.5–1.5）、对比度（0.5–1.5）、饱和度（0–2）、中间调 Gamma（0.5–2，大于 1 提亮）；Atkinson/Bayer 支持抖动强度（0–1）。先增强内容再补白边，避免改变白边颜色。
- 输出合法 4bpp 帧；预览直接由待发送帧重建，避免预览与编码不一致。
- 限制上传 10 MiB、解码 1600 万像素，拒绝其他格式；只保留一个共享草稿。其他浏览器重新生成预览后，旧草稿会过期，需重新生成。

调色板目前使用六种理想 RGB 色值，尚未按实物色卡测量校准，因此不能保证照片颜色准确度。抖动可改善视觉层次，但通常会增加高频像素变化；这不等于更低的刷新功耗。

## 新增刷新策略

1. 同一时刻只执行一个刷新任务，HTTP 请求立即返回，页面每 2 秒查询阶段。
2. 比较最后一次成功帧的 SHA-256，相同画面默认跳过，减少无意义闪烁。
3. 从任务完成或失败起，至少等待 150 秒才能再刷新；可勾选重复画面强制刷新，但不能跳过间隔。
4. 写入硬件前先持久化“画面未知”和间隔状态；只有完整刷新及深睡眠命令成功后才记录新指纹。失败不会误记为成功。
5. 状态默认写入 `var/hardware.json`，模拟用 `var/simulation.json`。重启遇到未完成任务会清除成功指纹并延长等待，以便重新确认面板。
6. 故障排查版本恢复 CLK 拉低后再设置 SDI 的明确写入顺序，暂时撤回合并 GPIO 写入优化。
7. 刷新命令后必须观察到 BUSY 忙→就绪过程；1 秒内未进入忙状态即报错，不继续发关高压/睡眠命令。1 秒是诊断超时策略，不是来自控制器 AC 规格的上限；若实测 BUSY 延迟或极性不同，需要依据测量修正。

硬件时序流程仍为原厂普通初始化、完整帧传输、高压开启、全刷、高压关闭、深睡眠。**没有实现未经资料支持的局刷、快速 LUT 或自定义高压波形**。上述策略减少重复刷新及 GPIO 调用开销，并不缩短一次面板波形执行时间；实际吞吐和闪烁需实板测量。

同一状态目录的服务器通过文件锁避免重复启动。运行硬件服务期间不要另开命令行驱动或使用另一状态目录启动硬件服务：GPIO 占用可以阻止同时申请，但不能替所有进程共享历史画面和刷新间隔。若外部程序改过屏幕，应在间隔结束后勾选重复画面刷新，以重新同步。状态目录应保持可写；更换板卡或面板时使用独立状态目录。

异常退出不能保证面板高压已关闭；页面任务失败时先检查 BUSY 和供电再恢复。当前没有自动清故障或绕过 BUSY 的操作。

## 验证

```sh
.venv/bin/python -m unittest discover -s tests -v
```

覆盖颜色编码/透明度/缩放/抖动、上传/免口令访问/预览、重入/重启/去重/冷却/失败恢复，以及底层 SPI 位序与 GPIO 调用次数。GPIO 实物、电气时序、实际光学效果仍待 Q8B 实板验证。

### 照片调参建议

先用“照片增强 + Floyd–Steinberg”作为基准；颗粒或斜向纹理明显时比较 Atkinson，喜欢规则点阵时比较 Bayer。暗部偏黑可把中间调设为 1.15–1.3，颜色过浓可降低饱和度。文字和色块用“原图 + 无抖动”。所有预览为近似 RGB，不替代实物色彩校准。新增算法是软件实现，处理耗时随 Q8B CPU 和图像变化，需要实际测量。

原始帧已修正为 720×480；旧版仅将网页变为横屏但仍按 480 像素行宽打包，现已取消该映射。原始帧每行 360 字节，总长仍为 172800 字节。更新后重新生成定位图及照片，不复用旧 bin；修正尚待实屏验证。

### 实屏错位 / 缺色诊断

选择“预览定位测试图（无抖动）”，该图直接生成六色色码，不经过调色板搜索或照片增强。包含黑/白/黄/红/蓝/绿六个色块及四角 1 TL、2 TR、3 BL、4 BR 标记。先提交全白，确认任务结果并拍照；等待间隔结束后提交定位图，再拍照对比网页预览。

- 全白仍有明显旧图：优先检查刷新是否完成、BUSY、电源及匹配的控制器初始化。
- 定位图四角重复或色块断裂：优先核对屏幕型号、扫描格式和 SPI 传输。
- 定位正确但纯色缺失或全部很浅：优先核对色码、供电和驱动板/屏幕匹配，再做照片调色。
- 六色色块正常、仅照片不佳：再比较照片量化算法及实物色彩校准。

日志会输出 `refresh: BUSY asserted` 和 `refresh: BUSY released`；任务失败时保留完整报错。错误会停止后续命令，不能保证硬件高压已关闭。不要反转 BUSY 极性来跳过报错。
